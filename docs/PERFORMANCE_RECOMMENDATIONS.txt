Gigawatt V0.10 — what to upgrade for performance
================================================
Date: 2026-09-05
Machine: SHC-2000, i.MX6 Quad (4× Cortex-A9), ~2 GB RAM, no swap,
/data ≈ 3.1 GB, Python 3.8, ffmpeg 4.2.2, Pulse, no apt.

This box is CPU- and disk-bound. The wins below are ordered by
how much they help TOSLINK / NAS / the web UI, not by how modern
they sound. Do not add Node, a second web framework, or HTTPS
termination until these are done.


Already done in this branch
---------------------------
1. TOSLINK “next track” no longer ffprobes the whole library.
2. Sign-in /api/auth/status no longer ffprobes every file.
3. /api/now caches host IP, RAM, and disk for 5 seconds.

On this VM, 13 files: probe 423 ms vs 0.1 ms without probe.
On the A9, that gap is the difference between a snappy skip and
a multi-second hitch.


Do these next (largest wins)
----------------------------

A. Stop polling the host like a desktop
   index.html hits GET /api/now every 1s while signed in, on every
   page. Each call still does: load player.json, host snapshot,
   AirPlay (and pactl when AirPlay is on but idle), DLNA, Spotify
   HTTP to 127.0.0.1:3678, NAS /proc/mounts.

   Change:
   - 1s only while TOSLINK / AirPlay / Spotify / DLNA is live.
   - 5–10s on Settings / Library / EQ when idle.
   - Stop the timer on the login gate (already does).
   - Split “now playing” from “inventory”. Settings RAM/disk does
     not need to ride the transport poll.

   Why: four background watchers already exist (HostPlayer,
   AirPlay, Spotify, DLNA). The browser does not need to wake
   Pulse and go-librespot every second while you browse artists.

B. Pause the visualizer
   requestAnimationFrame(tick) runs from boot of the app shell,
   even on Library / NAS / Settings. 60 fps canvas + analyser
   on an A9 while ffmpeg is decoding is wasted work.

   Change: run rAF only on the Now Playing view, or drop to
   8–12 fps when nothing is playing.

C. Make library metadata cheap
   GET /api/library still ffprobes every uncached file (4s
   timeout each). PROBE_CACHE dies at 400 entries and then
   wipes itself.

   Change:
   - Persist probes in /data/gigawatt/library-meta.json
     keyed by (rel, size, mtime).
   - LRU in memory, do not clear the whole map.
   - Probe in a background thread after a fast unprobed list.
   - Or skip probe unless the user opens a track row.

D. rclone cache for NAS
   Current mount: --vfs-cache-mode off, --dir-cache-time 30s,
   --attr-timeout 2s. Every album open and every TOSLINK read
   goes to SMB. FUSE + no cache is the slowest option rclone
   has.

   Change (safe on 3.1 GB /data):
     --vfs-cache-mode writes
     --vfs-read-ahead 8M
     --dir-cache-time 5m
     --attr-timeout 10s
     --vfs-cache-max-size 256M
   Keep the cache on /data (or /tmp if you accept reboot loss).
   Do not use full --vfs-cache-mode full on this partition
   without a size cap.

E. Stop restarting ffmpeg to change EQ
   HostPlayer.set_eq() kills the pipeline and seeks back. That
   is a decode restart + Pulse reopen on every slider settle.

   Better: Pulse module-equalizer-sink or a single long-lived
   ffmpeg/paplay with a FIFO of updated filter coeffs (harder).
   Next-best: apply EQ only when the user leaves the EQ page
   or taps a preset, not on every 0.5 dB drag.

F. Match TOSLINK instead of 48 kHz WAV
   Playback is: ffmpeg -ac 2 -ar 48000 -f wav | paplay.
   The jack is reported as 24-bit 96 kHz. Pulse then resamples
   48k → 96k. Two resamples + uncompressed WAV on a pipe is
   extra CPU.

   Try, in order:
   1. -ar 96000 -f s24le -ac 2 and paplay --raw
      --channels=2 --rate=96000 --format=s24le
   2. Or let Pulse convert once: ffmpeg -f wav without -ar
      if the file is already 44.1/48/96.
   Measure paplay CPU before/after with `top` on the host.


Worth doing, smaller
--------------------
G. load_player() on every /api/now reads player.json. Keep the
   last save_player() result in memory; write-through on change.

H. AirPlay snapshot should not run `pactl list sink-inputs`
   on every /api/now. The metadata thread already knows pbeg.

I. Spotify _watch already GETs /status every 1s. snapshot()
   should return cached fields, not hit the API again from
   /api/now.

J. Serve only index.html. A 17 MB go-librespot GET from the
   web root would wreck the LAN and the eMMC.

K. Self-host Manrope or drop it. The Google Fonts CSS is a
   WAN round trip on first paint.

L. NAS deep=1 walk: cap stays 2000, but prefer listing only
   the current album folder. Artist → Tracks should not walk
   every disc unless the user asked.


Do not upgrade yet
------------------
- Python 3.11+: no apt, Yocto 3.8 is the constraint.
- nginx back in front of port 80: possible later, not the
  first win. The cost is Python work, not HTTP framing.
- A JS bundler / React / Vite: the page is one file. A build
  step does not help the A9.
- HTTPS / Spotify Connect rewrite: product, not speed.
- Raising PBKDF2 rounds: login only; leave it.


Suggested order on 192.168.1.178
--------------------------------
1. Deploy this branch (skip probe + /api/now inventory cache).
2. Confirm TOSLINK skip and sign-in feel faster with a 50+
   file library.
3. Slow /api/now + pause the visualizer (client + one route).
4. rclone vfs-cache-mode writes with a size cap.
5. Pulse EQ or “apply EQ on release” so sliders do not restart
   ffmpeg.
6. Measure ffmpeg/paplay CPU and try 96 kHz s24le if TOSLINK
   is the main output.
